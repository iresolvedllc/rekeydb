# RDB and AOF corpus

The corpus is generated by the reference KeyDB server, never hand-written.

For each combination of type, encoding, and option:

1. Start KeyDB with a temporary `dir`.
2. Populate keys that exercise the encoding (small/large strings, intsets,
   ziplists, quicklists, skiplists, streams, expirations, subkey expirations).
3. `SAVE`, then copy `dump.rdb` here with a descriptive name.
4. Restart KeyDB from the file and record `DEBUG DIGEST`.
5. In rekeydb, load the file, compare `DEBUG DIGEST`, save a new RDB, load it
   in KeyDB, and compare again.

Corpus files are committed once they are stable. Use `MALLOC=libc` when
building the oracle to avoid allocator-dependent output.
