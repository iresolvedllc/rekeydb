# ADR 0006: RDB v9 and DUMP payloads

## Status

Accepted.

## Context

KeyDB persists with RDB version 9 and uses the same object payload for `DUMP`
and `RESTORE`, plus a two-byte RDB version and a CRC64 footer. RDB files and
`DUMP` payloads are both compatibility surfaces.

## Decision

- Implement RDB v9 directly in `rekeydb-persist`.
- Read the encodings KeyDB emits for our current types: raw/integer/LZF
  strings, quicklist-of-ziplist lists, intset and hash-table sets.
- Write valid RDB with raw strings and the legacy `RDB_TYPE_LIST`
  representation for lists. KeyDB loads this and converts it to a quicklist.
  Compact writers (quicklist, intset) follow once the encodings are shared with
  the in-memory representation.
- Use the Jones CRC64 implementation and verify it against KeyDB's known
  vector.
- `DUMP` emits KeyDB's `mvcc-tstamp` aux field before the footer; `RESTORE`
  skips auxiliary fields.
- `DEBUG DIGEST` mirrors KeyDB's XOR/mix algorithm, including ordered list
  mixing, unordered set XOR, database ids, and the expiration marker.

## Consequences

- RDB and DUMP files round-trip with KeyDB in both directions for strings,
  lists, sets, and expirations.
- `DEBUG RELOAD` and the full list conformance suite pass.
- Byte-level RDB parity for compact encodings remains future work.
